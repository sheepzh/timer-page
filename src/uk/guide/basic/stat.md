## Виміри статистики

Час і кількість візитів групуються та агрегуються за унікальним доменом і датою. Це означає, що дата та домен становлять найменшу одиницю статистичної деталізації.

Цей інструмент також дозволяє об'єднувати базові записи відповідно до власних потреб.

## Узагальнення даних споріднених сайтів

Як зазначено вище, дані агрегуються за доменом. Наприклад, `www.github.com` та `gist.github.com` рахуються як 2 окремі записи. Якщо ви хочете бачити агреговані дані обох сайтів, їх потрібно об'єднати вручну.

Більшість сторінок відображення даних підтримують запити з об'єднанням. Правила об'єднання можна налаштувати на дашборді.

### Як виглядають правила?

Правило складається з двох частин: джерела та цілі. Частина джерела визначає, які сайти підпадають під правило, а частина цілі — як ці сайти об'єднуються. Наприклад, `gist.github.com >>> github.com` — типове правило: ліве `gist.github.com` — це джерело, а праве `github.com` — ціль.

### Як визначити частину джерела?

Частина джерела може бути конкретним доменним ім'ям або Ant-виразом. Нижче наведено кілька прикладів.

| Частина джерела  | Приклади сайтів, що підпадають                                    |
| ---------------- | ----------------------------------------------------------------- |
| www.google.com   | Під правило підпадає лише `www.google.com`                        |
| www.google.com.* | `www.google.com.hk` `www.google.com.au`                           |
| \*\*.mit.edu     | `www.mit.edu` `libraries.mit.edu` `web.mit.edu` `foo.bar.mit.edu` |

### Як визначити частину цілі?

Частина цілі може бути конкретним доменним ім'ям, додатним цілим числом або залишитися порожньою. Нижче вони розглянуті разом із частиною джерела.

| Частина джерела      | Частина цілі | Вигляд                             | Примітка                                                                          |
| -------------------- | ------------ | ---------------------------------- | --------------------------------------------------------------------------------- |
| www.google.com.*     | google.com   | `www.google.com.* >>> google.com`  | Сайти, що підпадають під `www.google.com.*`, об'єднуються у конкретний `google.com`|
| www.google.com.hk    |              | `www.google.com.hk >>> Not Merge`  | `www.google.com.hk` не об'єднується через порожню частину цілі                     |
| \*\*\.\*\.google.com | 3            | `**.*.google.com >>> Keep Level 3` | Сайти, що підпадають під `**.*.google.com`, об'єднуються за трьома правими мітками |

У наведеній нижче таблиці — приклади об'єднання за цими правилами.

| Оригінальний сайт      | Правила, що спрацювали                                                  | Об'єднаний сайт і примітка |
| ---------------------- | ------------------------------------------------------------------------ | -------------------------- |
| www.google.com.au      | `www.google.com.* >>> google.com`                                        | google.com                 |
| www.google.com.pt      | `www.google.com.* >>> google.com`                                        | google.com                 |
| www.google.com.hk      | `www.google.com.* >>> google.com`<br/>`www.google.com.hk >>> Not Merge`  | www.google.com.hk **(1)**  |
| es.news.google.com     | `**.*.google.com >>> Keep Level 3`                                       | news.google.com            |
| b.c.photos.google.com  | `**.*.google.com >>> Keep Level 3`                                       | photos.google.com          |
| dept.cam.ac.uk       |                                                                          | cam.ac.uk **(2)**        |

::: tip

(1) Якщо спрацьовує кілька правил, частина джерела з конкретним доменним ім'ям має пріоритет

(2) За відсутності правил, що спрацювали, відбувається об'єднання до батьківського рівня [Public Suffix List](https://publicsuffix.org/)

:::
